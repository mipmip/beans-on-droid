## Context

The project must build the same way everywhere, and the Android toolchain is the
part most likely to drift. Pim's standing constraint is plain nix flakes with no
flake-utils.

## Goals

- One command (`nix develop`) yields a shell that can build an Android app.
- Supported systems are visible in the file rather than generated by a helper.
- `nix flake check` is fast and always runnable.

## Decisions

### Systems via `genAttrs`, not flake-utils

`systems` is a literal list and `forAllSystems` is
`nixpkgs.lib.genAttrs systems (system: f (pkgsFor system))`. This keeps the set
of supported systems greppable and removes an input.

### `nixpkgs` is imported per system with a config

`androidenv` packages are unfree and require license acceptance, so `pkgsFor`
imports nixpkgs with `allowUnfree = true` and `android_sdk.accept_license = true`
rather than using `nixpkgs.legacyPackages`.

### Android SDK versions are pinned explicitly

`composeAndroidPackages` is given exact versions. A nixpkgs bump that drops a
version fails the flake at evaluation time, which is a loud, early failure rather
than a silent toolchain change. Emulator, system images, sources and NDK are
excluded to keep the closure small.

### The Gradle build is NOT a flake check

Gradle resolves dependencies over the network, and a nix derivation builds in a
sandbox without network access. Making the Android build a pure derivation would
mean vendoring every Maven dependency, which is a project in itself and out of
scope for a Phase 1 PoC.

So `checks` holds only what is pure: `shellcheck` over `scripts/` and
`nixpkgs-fmt --check` over `flake.nix`. The real build gate lives in
`scripts/gate.sh`, which runs `nix flake check` and then the Gradle build inside
`nix develop`.

Alternatives considered:
- Vendor Maven dependencies into the store with a fixed-output derivation.
  Rejected: large effort, brittle across dependency bumps, no benefit for a PoC.
- Use `__noChroot`. Rejected: not portable, and it makes the check impure while
  pretending otherwise.

### aapt2 comes from the SDK

AGP normally downloads `aapt2` from Maven. `GRADLE_OPTS` sets
`android.aapt2FromMavenOverride` to the `aapt2` in the nix-provided build-tools,
so the binary used is the one the flake pinned.

## Risks

- A nixpkgs bump can drop a pinned SDK version and break evaluation. Accepted:
  the failure is immediate and the fix is a one-line version bump.
- `nix flake check` only checks the current system by default. Accepted for a
  PoC; `--all-systems` is available when it matters.
